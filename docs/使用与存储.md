# 自动记忆

从个人 Pi 工作会话中积累可复用经验，减少重复说明项目入口、有效流程和个人偏好。记忆保存在 `~/.agents/memory/`，通过 Markdown 阅读和关键词搜索，不需要数据库、embedding 或外部检索服务。

典型场景包括跨天继续工作、数周后回到项目、再次遇到相似错误，以及用户对助手行为的明确纠正。知识价值不取决于最近是否被查询：低频但稳定的配置约定应长期保留，未经采纳的建议也不应成为事实。处理预算、来源证据和知识有效性分别判断。

## 如何积累

1. TUI 持久会话启动及每轮对话完成时，自动登记会话 ID、文件路径和工作目录。
2. 会话启动时，后台选择已登记、非当前、最后修改至少 30 分钟的历史。没有历史年龄上限；等待最久的来源先处理，每次最多提取两个。
3. 阶段一调用当前模型，保存经验和来源摘要。文件未变化且已成功提取时跳过；没有可复用经验时允许空输出。
4. 阶段二只归并新增或变化的有效记录，与已有手册合并。预算不足的记录保持待处理状态，旧知识和来源摘要持续保留。
5. Markdown 和来源摘要组成完整快照，通过 `current` 软链接原子切换。失败时保留旧快照和已完成的提取结果。

启动 Pi、新建或切换会话会触发后台整理；`/reload` 只重载扩展与摘要，不保证重新启动整理任务。每轮对话完成只登记来源；退出取消任务。没有定时轮询，空闲达到 30 分钟不会自行唤醒任务，需要下次启动或手动触发。

只处理加载本扩展后登记的 TUI 持久会话；临时会话、RPC、print、json 不参与，也不会扫描未登记的全部旧历史。空闲窗口按文件修改时间判断，并不是跨进程的会话存活检测；提取期间源文件再次变化时放弃结果。

## 如何召回

短摘要进入当前会话的系统提示词。摘要足以提供背景时直接使用；只有额外细节、证据或历史决策可能影响答案时，才调用 `memory_search` 搜索 `MEMORY.md`，必要时读取条目指向的 `rollout_summaries/`。

检索使用英文标识符和中文二元词匹配，返回最多五个主题段落。搜索不写状态，不统计返回次数，也不以此评价知识的重要性。历史记忆仍需核对项目范围和时效，重要判断以当前源码和用户指令为准。

后台整理不占用常驻状态栏；`/memory status` 查看简明状态，`/memory debug` 查看目录、原始失败记录和费用。失败仍通过通知反馈。

后台更新默认不改变当前会话已载入的摘要。新会话自动载入，当前会话可用 `/memory reload` 刷新。`/memory run` 遵守失败退避，退避不是定时任务，到期后需再次触发；需要立即跳过当前退避时使用 `/memory retry`。

## 命令与设置

| 命令 | 用途 |
| --- | --- |
| `/memory`、`/memory status` | 查看简明状态、失败原因和下一步操作 |
| `/memory debug` | 查看目录、原始失败记录和额外模型费用 |
| `/memory on`、`/memory off` | 开启或关闭积累与召回；关闭取消后台任务 |
| `/memory run` | 手动触发后台整理，仍遵守空闲窗口和失败退避 |
| `/memory retry` | 清除当前归并退避并立即重试一次 |
| `/memory reload` | 重读当前摘要，不调用提取或归并模型 |
| `--no-memory`、`PI_MEMORY=0` | 启动时关闭扩展的记忆功能 |

`PI_MEMORY_DIR` 覆盖默认根目录。`PI_MEMORY_IDLE_HOURS` 调整空闲窗口，默认 `0.5`；设为 `0` 可在试验中取消等待，仍然排除当前会话。`PI_MEMORY_MODEL_TIMEOUT_MS` 调整单次模型请求超时，默认 `600000` 毫秒；无效值或低于 10 秒时回退默认值。

独立试验可以使用临时记忆目录，并通过 `--no-extensions -e ./src/index.ts` 只加载本扩展。第一场会话完成任务后，新建另一场会话触发历史提取。日常使用恢复默认空闲窗口。

每次正常整理最多两个提取请求、一个归并请求，使用当前模型并产生额外费用。`/memory debug` 中的费用只统计本扩展实例，不合并进宿主主对话统计。输入按文本长度预算控制，输出受当前模型 token 上限限制；这不是精确的 tokenizer 计费或额度门禁。

## 存储与维护

```text
~/.agents/memory/
├── candidates/                  # 会话 ID、原始路径与工作目录
├── stage1/                      # 提取记录、源指纹及失败退避
├── generations/                 # 完整发布快照，保留最近两代
├── current -> generations/...
│   ├── memory_summary.md        # 短摘要
│   ├── MEMORY.md                # 主题手册
│   ├── rollout_summaries/       # 累积来源摘要，含原始路径
│   └── state.json              # 各来源已归并的指纹，不重复保存正文
└── phase2-retry.json            # 归并失败退避、时间和脱敏错误原因
```

不因来源年龄、低频使用、原始文件消失或本轮预算不足而自动删除知识。新证据或用户纠正可以让模型修正失效结论，格式检查不能保证其语义正确。

可以人工编辑 `current/MEMORY.md` 和 `current/memory_summary.md`。归并期间检测到正文修改时放弃发布，保留人工版本。直接删除条目不是永久遗忘协议，来源后续更新仍可能让它再次出现；当前没有独立的 remember/forget 命令。

原始 Pi 会话不改写、不删除。提取记录和来源摘要持续保留，会随使用增长；仅发布快照回收至最近两代。保留两代便于恢复上一版，但不提供无限历史备份。`~/.agents` 只是存放位置，其他 Agent 不会自动读取或兼容本扩展的数据。

写锁为 `.pipeline-lock/`；死进程锁可自动回收，活进程锁不抢占。缺失或损坏 owner 文件时等待两分钟安全窗口后自动回收，避免误删仍在初始化的锁。锁回收使用 `.lock-recovery/` 互斥；该目录因崩溃残留时同样在两分钟后恢复。

提取输入和模型输出做常见凭据模式脱敏，并要求模型不保存敏感值。记忆文件在本机，输入仍会发送给当前模型服务；模式识别不能保证覆盖所有敏感信息。

## 实现组织

```text
src/
├── index.ts                     # 扩展装配：事件、命令、工具
├── read.ts                      # 召回流程：摘要、指引与关键词搜索
├── write.ts                     # 写流程：提取、归并及所属策略/接口
└── lib/
    ├── runtime/                 # 运行协调与 Pi 适配
    │   ├── controller.ts        # 生命周期、排队、取消、状态与费用
    │   ├── session.ts           # Pi 会话读取与可见消息裁剪
    │   └── model.ts             # Pi 模型调用与费用回传
    ├── templates/               # 召回.md、提取.md、归并.md
    └── foundation/              # 基础能力，不依赖上层
        ├── storage.ts           # 文件布局、状态、来源和快照 I/O
        ├── lock.ts              # 跨进程写互斥
        ├── prompts.ts           # 模板资源加载
        ├── model.ts             # 输出契约与共同脱敏
        └── types.ts             # 来源、提取记录和快照数据契约
```

`read.ts`、`write.ts` 与入口平铺在扩展目录，承载记忆业务流程；`lib/` 提供运行适配和基础能力。代码按职责和依赖分层：入口装配 → 运行协调 → 记忆流程 → 基础能力。上层可以向下调用，下层不反向导入上层；配置和类型跟随所属职责放置。

| 层次 | 负责 | 依赖边界 |
| --- | --- | --- |
| `index.ts` | 将 Pi 事件、命令与工具绑定到运行协调和召回流程 | 不直接读写记忆文件或发起模型请求 |
| `lib/runtime/` | 适配 Pi 会话与模型，管理任务生命周期及费用 | 依赖流程契约和基础能力；提供模型调用、会话读取回调 |
| `read.ts`、`write.ts` | 决定何时处理哪些来源、如何归并、如何召回 | 不导入 Pi SDK 或 `runtime/`，不直接操作文件系统 |
| `lib/foundation/` | 执行文件读写、锁、模板加载、格式校验与脱敏 | 不依赖入口、运行协调或记忆流程，不决定提取与遗忘策略 |

读代码从 `index.ts` 进入：后台任务沿 `lib/runtime/controller.ts` → `write.ts` 的 `runPipeline` → `extractHistory` → `consolidateHistory` 阅读；召回直接进入 `read.ts`。两条流程通过 `lib/foundation/storage.ts` 访问数据。宿主 SDK 的会话读取和模型调用集中在 `lib/runtime/session.ts`、`lib/runtime/model.ts`；流程只通过 `readSession`、`ModelCall` 接口使用它们，不持有 Pi 上下文。

`write.ts` 集中维护写流程及其策略和接口，提取与归并是模块内部步骤；`lib/foundation/types.ts` 维护持久化数据契约；运行目录及宿主模型预算归运行协调层。基础层不会为了访问配置而反向导入流程层。

提示词正文维护在 `src/lib/templates/*.md`，修改后重载扩展或重启 Pi 生效。召回模板的 `{{ root }}`、`{{ summary }}` 在渲染时替换。模板是包资源，不注册为用户工作流预设；修改输出字段或长度约束时同步核对 `src/lib/foundation/model.ts`。
