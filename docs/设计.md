# 记忆处理设计

## 设计决策

决策日期：2026-10-01。适用范围：个人长期使用的 Pi TUI 工作会话。具体契约由本扩展的需求与调用链确定，参考实现不作为必须复刻的协议。

### 登记范围与触发时机

只处理已登记历史，是为了明确处理范围并控制初次模型费用；需要全量历史回填时再设计显式入口。整理放在会话启动与手动命令上，避免每轮回答后都产生额外模型请求。按等待顺序消化积压，避免新会话持续进入时，旧经验一直得不到处理。

30 分钟是初始体验参数：让刚切换的工作有机会继续，又允许同一天的后续会话积累经验。它是启发式静默窗口，不证明其他进程已停止使用该会话。该参数需要在真实使用中校准，可通过 `PI_MEMORY_IDLE_HOURS` 调整。

### 处理预算与费用

两个提取名额是个人后台积累的初始费用上限，允许历史逐步消化；手动多次运行会分别产生费用。提取与归并串行执行。

归并预算按实际序列化输入长度计算，包含完整手册、当前摘要、已有来源 ID 和本轮增量，而不是用磁盘 JSON 大小近似。

| 情况 | 行为 |
| --- | --- |
| 没有新的有效提取记录 | 不调用归并模型 |
| 部分记录放得下 | 处理这部分，其余保持待处理 |
| 没有一条放得下 | 暂停归并，保留已有手册及全部待处理记录 |
| 模型请求或输出校验失败 | 不更新归并检查点，保留旧快照 |
| 归并成功 | 只更新本轮消费来源的指纹 |

运行输入预算最多 64000 字符，并按当前模型上下文缩小；输出请求上限最多 8192 tokens，也受模型自身限制。文本长度预算是保守的工程约束，不提供精确 token 计数保证。

原始文件最多 20 MiB、历史可见文本最多 48000 字符、单条消息最多 8000 字符，用于限制内存和模型输入，不能据此认定被跳过或截断的知识无价值。提取经验最多 10000 字符、来源摘要最多 9000 字符、手册最多 48000 字符、短摘要最多 6000 字符；这些是本版响应与常驻上下文上限，后续根据质量、成本和模型窗口调节。

完整手册增长到无法容纳任何增量时暂停。当前不做自动分片归并，也不通过静默丢弃知识解决容量问题。失败退避初始为一小时，单次模型请求超时为两分钟，避免异常在频繁启动时重复收费和长期占用任务；取消不标记成功，后续从持久化成果继续。

### 增量检查点与证据保留

`state.json` 中的 `sources` 是来源 ID 到已成功归并指纹的映射。归并选择指纹与检查点不同的非空经验，按提取生成时间从早到晚处理；已消费且未变化的记录不重复送入模型，不按访问频次排序。

归并输入的字段各有明确用途：

- `previous`：完整旧手册；
- `currentSummary`：已有短摘要；
- `existingSources`：已经归并且保留摘要的来源 ID；
- `records`：本轮新增或更新的证据。

一个来源没有出现在 `records` 中，只说明本轮没有提供它，不表示删除。更新引用时只能使用已有来源或本轮来源 ID。发布时复制原有来源摘要，再写入本轮新增或更新的摘要；同一会话再次提取后更新该 ID 的摘要，它仍指向同一个原始会话文件。

低收益空输出有提取检查点，但不触发归并，也不抹掉曾经积累的结论。缺少新信号不是旧知识失效的证据。

### 知识有效性与遗忘

不统计搜索返回次数，因为返回不是采用，摘要和直接读文件也无法形成一致的使用统计。用户纠正、新验证结果或环境变更证据才是修正知识的依据。

原始文件消失后，已保存的来源摘要仍提供历史线索，但不能冒称原始证据仍可读取。本版以可恢复和不误删为优先，持续保留提取记录与来源摘要；出现实际磁盘压力后再设计可审阅的归档或清理能力，不预建后台 GC 框架。

### 文件职责与发布方式

每份文件只承担一个用途：摘要提供导航，手册保存详细结论，来源摘要保存历史证据，检查点记录成功消费进度，阶段记录支持失败恢复。正文只保存在 Markdown 中，不重复写入检查点。

不生成 `raw_memories.md`，因为归并直接接收结构化记录，没有文件消费者。摘要直接输出正文，不设格式版本首行，不引入未发生的格式迁移框架。

完整快照和原子切换避免新摘要与旧手册混用；跨进程锁避免并行覆盖。保留最近两代支持恢复上一版，而非无限历史备份。

### 召回与可复用操作证据

摘要足以提供背景时直接使用，只有额外细节或证据可能改变答案时再检索，避免固定执行全部读取步骤。

提示词区分用户要求、工具验证、助手建议和失败尝试，保留适用项目与验证状态。允许保存经过验证且值得复用的短命令、配置片段、函数名和准确报错，不以禁止所有可执行代码阻断工程经验。输出契约、长度和脱敏由代码校验，语义正确性仍需真实使用检验。
