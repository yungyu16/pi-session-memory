# 轻量文件记忆设计

## 目标与主流程

让当前 Agent 保存值得跨会话复用的信息，并在需要时找到它。扩展负责连接 Pi 与本地文件目录，模型负责判断内容与维护主题。

1. 用户发送消息前，扩展准备记忆目录、读取入口索引。
2. 系统提示词提供目录、索引和简短的读写规则。
3. 当前 Agent 按需读取主题，使用宿主工具保存或修正记忆。
4. 下一轮重新读取索引，新会话也能找到已经保存的主题。

不会遍历会话历史，也没有独立的提取模型、归并模型、任务队列或检查点。普通对话中的工具调用就是读写过程，失败时通过宿主工具返回错误，由当前 Agent 决定如何处理。

## 文件职责

`MEMORY.md` 只提供主题链接与简短说明。每个主题保存在 `topics/` 下的 Markdown 文件中，记录适用项目、日期、结论和必要的证据或未验证事项。格式由内容决定，不要求 JSON 响应或统一 frontmatter。

模型先检查已有主题，尽量局部更新；新建主题时先写正文，再添加索引入口。索引和主题文件不是事务，意外中断或并发编辑仍可能留下缺失链接，应通过正常文件读取与编辑修复。扩展不为此维护快照或恢复状态机。

记忆目录默认跨项目共享。提示词要求保留项目与条件边界，防止把局部约定当作全局规则。不会将用户指令文件纳入自动记忆维护。

## 索引载入

索引最多载入前 200 行、25000 UTF-8 字节；固定使用说明与裁剪提示另计。先按行选取，再检查字节量，尽量在完整行处结束；单行过长时保持 UTF-8 边界。这里明确使用真实字节数，不将字符数视为精确 token 数。

超出上限只裁剪本轮上下文视图，并提醒 Agent 将细节移到主题文件。磁盘上的索引不会被扩展改写。主题文件没有扩展施加的整体大小上限，由宿主读取工具按需提供内容。

每次 `before_agent_start` 重读索引，不缓存正文。模型刚更新的入口在下一轮就能生效，不需要单独的刷新命令。索引不存在视为尚无记忆；其他读取错误显示通知，并避免注入上一轮旧内容。

## 代码结构

```text
src/
├── index.ts            # Pi 事件、开关、命令和错误通知
├── memory.ts           # 目录准备、索引读取与提示词渲染
└── templates/记忆.md   # 当前 Agent 的记忆读写规则
```

只有入口依赖 Pi SDK。文件逻辑使用 Node.js 标准库，提示词相对模块定位，避免依赖启动目录。索引限制集中在 `memory.ts`，渲染时填入模板，避免文案与代码漂移。

扩展不注册专用记忆工具，不启用被用户关闭的工具，也不改变宿主权限。只有 TUI 持久会话会载入记忆提示；RPC、print、json 和临时会话保持原有执行方式。

## 参考与取舍

参考 [Claude Code auto memory](https://code.claude.com/docs/en/memory#auto-memory) 的索引、主题文件和普通工具读写方式。采用其基础思路，不要求复制其项目目录编码、分类体系或后台服务。

自动记忆依赖当前模型遵循提示词，不承诺完整提取每段对话或自动整理所有旧知识。扩展越过模型判断做后台补全会重新引入额外调用和状态管理，因此当前实现只保留文件记忆入口。需要保证保存的重要事项，应明确要求 Agent 记住，并检查写入结果。

## 验证范围

自动测试验证实际文件读取、UTF-8 与行数边界、文件不被载入过程改写、宿主事件与开关、错误通知、模式隔离以及包入口加载。测试中的宿主模型调用会直接报错，以防重新引入后台调用。

模型主动保存的时机、事实质量、并发会话的编辑结果和真实 TUI 使用效果，需要实际会话验证；单测通过不代表这些行为已经得到保证。
