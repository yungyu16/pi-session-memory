# pi-session-memory

为 Pi 提供本地文件记忆：从历史工作会话提取可复用经验，增量归并到 Markdown 手册，在后续会话中提供短摘要和按需搜索。无需数据库、embedding 或独立检索服务。

适合跨天继续工作、数周后回到项目、复用排障经验，以及记住用户明确纠正的行为偏好。目前为实验性版本：处理流程有自动测试，真实模型的记忆质量、费用和长期使用效果仍需持续验证。

## 安装

需要 Pi 0.86.1+、Node.js 22.6+，以及可调用的当前模型。

```bash
pi install git:github.com/yungyu16/pi-session-memory
```

安装后执行 `/reload` 或重启 Pi。默认安装不固定版本，跟随 `main`；提交推送后通过 `pi update` 获取更新：

```bash
pi update git:github.com/yungyu16/pi-session-memory
```

如需固定某个发布版本，可以在安装来源末尾加 tag，例如 `@v1.0.0`；固定版本不会自动跟随 `main`。

本项目以 Git 包分发，GitHub 仓库公开；`package.json` 的 `private: true` 仅用于防止意外发布 npm。不依赖 my-pi 或个人配置仓库。

## 工作流程

1. 加载扩展后，登记 TUI 持久会话的 ID、路径和工作目录。
2. 后续启动、新建或切换会话时，后台选择已登记且非当前的空闲历史；默认要求最后修改至少 30 分钟。`/reload` 只重载扩展与摘要，不保证重新启动整理任务。
3. 调用当前模型提取经验，再与已有手册增量归并，保存来源摘要。
4. 新会话载入短摘要；需要更多细节时，模型使用 `memory_search` 搜索手册，必要时读取来源摘要。

每轮结束只登记来源，不触发整理。没有定时轮询，也不会扫描未登记的全部历史。第一次安装时尚无已登记历史，需要完成会话并在后续会话中触发整理。

## 命令与配置

| 入口 | 用途 |
| --- | --- |
| `/memory` / `/memory status` | 查看简明状态、失败原因和下一步操作 |
| `/memory debug` | 查看路径、原始失败记录和本扩展模型费用 |
| `/memory on` / `/memory off` | 启用或关闭积累与召回，关闭时取消后台任务 |
| `/memory run` | 手动触发后台整理，仍遵守空闲窗口与失败退避 |
| `/memory retry` | 清除当前归并退避并立即重试一次 |
| `/memory reload` | 重读当前摘要，不调用模型 |
| `--no-memory` / `PI_MEMORY=0` | 启动时关闭 |
| `PI_MEMORY_DIR` | 覆盖默认目录 `~/.agents/memory/` |
| `PI_MEMORY_IDLE_HOURS` | 调整空闲窗口，默认 `0.5` 小时 |
| `PI_MEMORY_MODEL_TIMEOUT_MS` | 调整单次模型请求超时，默认 `600000` 毫秒 |

后台更新不改变当前会话已载入的摘要；整理成功后可用 `/memory reload` 刷新。`/memory run` 遵守失败退避，退避不是定时任务，到期后需再次触发；需要立即跳过当前退避时使用 `/memory retry`。日常状态看 `/memory status`，路径、原始错误和费用仅在 `/memory debug` 展示。命令开关不持久化。

## 费用、数据与边界

**默认会在符合条件时后台调用当前模型并产生额外费用。** 每次整理最多两个提取请求和一个归并请求，手动多次运行会分别计费；费用通过 `/memory debug` 查看，不合并到宿主主对话统计。

- 历史会话文本会发送给当前模型提供方，经验和来源摘要存放在本机记忆目录。代码包含脱敏处理，但不能保证识别所有敏感内容；不要把本地记忆目录或真实会话提交到公开仓库。
- 只处理加载扩展后登记的 TUI 持久会话，临时会话、RPC、print、json 不参与。30 分钟窗口是文件静默时间，不证明其他进程已停止使用该会话。
- 文件快照通过 `current` 软链接切换，失败保留旧快照与已完成的提取结果；模型可能提炼错误，重要判断仍应核对当前源码与用户指令。
- 手册无法与任何增量一起放入输入预算时，归并暂停并保留现有知识，需要人工精简或选择更大上下文模型。本版不自动分片或淘汰低频知识。

完整设置、存储布局和人工维护说明见 [使用与存储](docs/使用与存储.md)，处理预算、证据保留及设计取舍见 [设计](docs/设计.md)。

## 开发与验证

使用 `.nvmrc` 声明的 Node.js 版本：

```bash
npm ci
npm run check
npm test
npm pack --dry-run
```

测试使用临时目录与模型桩，覆盖两阶段恢复、增量预算、旧知识和来源保留、锁、取消、退避、人工编辑保护、Pi 会话读写及独立 loader 发现。不调用真实模型，不修改真实记忆目录；真实模型质量、实际费用与 Pi 交互仍需人工验收。

Pi 核心依赖由宿主提供，无额外运行时第三方依赖。源码统一放在 `src/`，`pi.extensions: ["./src/index.ts"]` 显式声明入口，不依赖目录发现约定。无需编译，Pi 直接加载 TypeScript；三个中文提示词模板随包分发。

锁定的开发用 Pi SDK 间接依赖 `brace-expansion` 当前有 `npm audit` 高危告警，常规依赖更新未能消除；本包不通过覆盖宿主依赖来修复，运行时 SDK 由安装者的 Pi 提供。
